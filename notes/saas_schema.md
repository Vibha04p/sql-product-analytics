# SaaS Schema Documentation

This document summarizes the SaaS database schema explored during the schema reconnaissance phase. It includes the table inventory, business meaning of key columns, verified relationships, data quality observations, and exploratory findings used to prepare for SQL product analytics.

## B. Column Dictionary

### accounts

| Column | Description |
|--------|-------------|
| account_id | Unique identifier for each customer account. |
| name | Customer account or company name. |
| account_type | Indicates whether the account is self-serve or B2B. |
| industry | Industry to which the customer belongs. |
| employee_count | Number of employees in the organization. |
| country | Country where the account is located. |
| signup_date | Date and time when the account was created. |
| acquisition_channel | Marketing channel through which the account was acquired. |


### users

| Column | Description |
|--------|-------------|
| user_id | Unique identifier for each user. |
| email | User's email address. |
| company_name | Company associated with the user. |
| signup_date | Date and time when the user signed up. |
| signup_source | Marketing or referral source through which the user registered. |
| plan_type | Subscription plan associated with the user. |
| is_active | Indicates whether the user account is active. |
| last_login_date | Timestamp of the user's most recent login. |
| account_id | References the account to which the user belongs. |
| role | User's role within the account (owner, admin, member, etc.). |

### subscriptions

| Column | Description |
|--------|-------------|
| subscription_id | Unique identifier for each subscription. |
| user_id | User associated with the subscription. May be NULL for account-level subscriptions. |
| plan | Name of the subscription plan. |
| start_date | Date when the subscription began. |
| end_date | Date when the subscription ended. |
| mrr | Monthly Recurring Revenue generated by the subscription. |
| status | Current lifecycle status of the subscription. |
| cancelled_at | Timestamp when the subscription was cancelled. |
| cancellation_reason | Customer-provided reason for cancellation, if available. |
| account_id | References the account associated with the subscription. |
| seat_count | Number of seats/licenses included in the subscription. |
| plan_id | References the subscription plan in the `plans` table. |

### subscription_events

| Column | Description |
|--------|-------------|
| event_id | Unique identifier for each subscription event. |
| subscription_id | References the subscription affected by the event. |
| user_id | User associated with the event, when applicable. |
| event_type | Type of subscription lifecycle event. |
| event_time | Timestamp when the event occurred. |
| from_plan | Previous subscription plan before the change. |
| to_plan | New subscription plan after the change. |
| mrr_delta | Change in Monthly Recurring Revenue caused by the event. |
| account_id | References the account associated with the event. |
| actor_user_id | User who initiated the event. |
| seats_delta | Change in the number of seats resulting from the event. |

### plans

| Column | Description |
|--------|-------------|
| plan_id | Unique identifier for each subscription plan. |
| plan_name | Name of the subscription plan. |
| monthly_price | Monthly subscription price for the plan. |
| seat_limit | Maximum number of seats allowed under the plan. |

## E. Data Quality Findings

1. subscriptions.status
   - Five distinct status values were identified: active, churned, trialing, past_due, and paused.
   - No inconsistent casing or duplicate spellings were observed.
   - No unexpected status values were found.

2. subscriptions.plan
   - Detected inconsistent casing in plan names (e.g., `pro` vs `Pro`, `enterprise` vs `Enterprise`).
   - Observed both `pro` and `professional`, which may represent inconsistent naming conventions or distinct product tiers. Additional business validation is required before standardizing these values.
     
3. accounts.account_type
   - Two account types were identified: `self_serve` and `b2b`.
   - Values are consistently formatted with no inconsistent casing or duplicate spellings.

4. subscription_events.event_type
   - Seven distinct event types were identified: subscription_started, trial_started, cancelled, plan_changed, seat_add, trial_converted, and addon_attach.
   - Values are consistently formatted using lowercase and underscores.
   - No inconsistent casing or duplicate event names were observed.

## F. Six Probe Questions

### 1. What is the grain of the subscriptions table?

**Answer:**
The subscriptions table contains two different grains:

- User-level subscriptions: 2,000
- Account-level subscriptions: 113

User-level subscriptions are linked to individual users, whereas account-level subscriptions belong to an account rather than a specific user.

---

### 2. Do self-serve subscriptions always have one seat?

**Answer:**
Yes.

All 2,000 user-level subscriptions have a seat count of 1, confirming that self-serve subscriptions are single-seat subscriptions.

---

### 3. Do account-level subscriptions support multiple seats?

**Answer:**
Yes.

Among the 113 account-level subscriptions:

- 108 have multiple seats.
- 5 have a single seat.

This suggests that account-level subscriptions are primarily designed for multi-seat (B2B) customers, although a small number of account-level subscriptions currently have only a single seat.

### 4. What subscription statuses exist?

The subscriptions table contains five lifecycle statuses:

- active
- churned
- trialing
- past_due
- paused

The values are consistently formatted with no duplicate spellings or inconsistent casing.

### 5. What subscription event types exist?

Seven event types were identified:

- subscription_started
- trial_started
- cancelled
- plan_changed
- seat_add
- trial_converted
- addon_attach

The values are consistently formatted using lowercase and underscores.

### 6. What billing intervals are available?

The plans table contains two billing intervals:

- monthly (4 plans)
- annual (4 plans)

Both billing frequencies are represented equally, indicating that the dataset supports monthly and annual subscription plans.

## Summary

The schema reconnaissance confirmed the primary business entities, validated key relationships, identified minor data quality issues, and established the distinction between user-level and account-level subscriptions. These findings provide the foundation for the SQL product analytics tasks that follow.
